# 0018. 会话日志落盘：别和游戏抢 latest.log

- **Status**: Accepted
- **Date**: 2026-10-25
- **Deciders**: @liming
- **Depends on**: ADR-0010

## Context

ADR-0010 让游戏的每一行输出都变成 `OpEvent`，但那是**流**——进程退出后，除了内存里留的 40 行 tail，什么都没剩下。

诊断能力再强，现场没了也是白搭。玩家说「刚才崩了」，你只能问「还记不记得报什么错」。

## Decision

### 1. 每次 run 写一份独立日志

```
<gameDir>/logs/2026-10-25T11-57-12-1.20.1.log
```

文件名是 `时间戳-版本.log`，不是固定的 `latest.log`。

理由：同一个实例可能今天跑原版、明天跑 Forge。固定名会互相覆盖，而**崩溃现场最怕的就是「上一次的被这次冲掉了」**。

### 2. 保留 10 个，按 mtime 淘汰

一次会话几 MB，10 个足够回溯到一个小时内的多次尝试。

### 3. 轮转只碰自己的文件

这是实现时踩到的坑：目录里除了我们写的日志，还有 **Minecraft 自己写的 `latest.log`**（内容和我们的一致）。

```ts
const OUR_LOG = /^\d{4}-\d{2}-\d{2}T/
```

`prune` 只匹配这个模式的才删。如果按「所有 .log 按时间排序删最旧」处理，第一个被删的就是 `latest.log`——那是游戏自己的日志管理，动了会让依赖它的工具（崩溃分析器、日志上传器）读不到东西。

同理 `listLogs` 会标出哪些是游戏原生的：

```
2026-10-25T11-57-12-1.20.1.log  4 KB · 1 分钟前
[游戏原生] latest.log  4 KB · 1 分钟前
```

## Consequences

**Positive**

- 崩溃现场留下来了，`run` 结束时会打印完整路径。
- 崩溃时的提示从「下一步：跑 preflight」变成「完整日志 + 下一步」，用户能自己先看一眼。
- 日志和实例绑定（`<gameDir>/logs`），换实例不会混。

**Negative**

- **磁盘占用没有上限控制**：10 个日志，如果每个都很大（几百 MB 的调试日志），总量可观。没有按大小淘汰。
- 没有压缩，没有归档。
- 只存不看——没有内置的日志分析（比如提取异常堆栈、匹配已知崩溃模式）。
- 写入失败时静默跳过（`write` 里 catch 掉了），用户不会知道日志没落盘。

## 实测

```
$ blockpilot run 1.20.1 --root fixtures/mcroot --stop 15

  异常退出  code=- signal=SIGTERM · 15.2s · 39 行日志
  完整日志  D:\...\instances\default\logs\2026-10-25T11-57-12-1.20.1.log
```

文件内容与 stdout 完全一致，39 行对 39 行。

5 个单测覆盖：写入/关闭、文件名净化、轮转不删原生日志、`native` 标记、目录不存在。
