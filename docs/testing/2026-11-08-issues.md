## 三条值得记住的坑

1. **`\s` 会跨行。** E2E-301 第一版改成 `/日志\s+(.+?\.log)/m` 仍然失败：
   `日志` 先匹配到上一行的「326 行日志」，`\s+` 吃掉换行，于是把「日志  D:\...」整个当成了路径。
   正确写法是行首锚定 + `[ \t]+`。
2. **「进程还活着」不是证据。** 未捕获异常打在渲染线程上时 JVM 不退出，`--stop` 到点
   我们照样 exit 0。只有日志心跳（安静 ≥20 s 且以栈帧收尾）能区分这两种情况，
   而健康但安静的整合包不会被误判，因为第二条判据不成立。
3. **兜底表会盖过模组自己的声明。** BTWCE 在 1.6.4 上要求 Java 17–21，而「MC 版本 → Java」
   推出来是 8。有 mod 声明时必须以声明为准，否则两条建议互相矛盾，用户照哪条都可能装坏。

## 附：真机验一次新命令（23:23–23:37）

不是发版验证，是「照 README 敲一遍」：

```
blockpilot forge 1.20.1 --root fixtures/mcroot --instance forge-cli --loader 47.3.22
  原版就绪  下载 1 · 跳过 65 · 原生库 54 个
  完成 forge 47.3.22 · 已跑官方 installer          # 2m54s，exit 0

blockpilot run 1.20.1-forge-47.3.22 --root fixtures/mcroot --instance forge-cli
  → Sound engine started / 全部 atlas 创建完成     # 没有 UnsatisfiedLinkError: lwjgl.dll
```

issue #13 里「手工装完 Forge 直接 run 会缺 natives」那条，在 `forge` 子命令下不复现：
它先跑原版 setup（解压 54 个原生库），再跑 installer。

同时撞出两个问题，都已修：

1. **`ASSETS_MISSING` 的提示不可执行**：给的是 asset index id（1.20.1 的 index 叫 `5`），
   `blockpilot assets 5` 会去取 `versions/5/5.json`，直接 404。改为提示 MC 版本。
   照修好的提示实跑：`assets 1.20.1` 补齐 fixtures 里真实缺失的 143 个对象
   （86.8 MB，0 失败），复检 verdict 从 WARN 回到 OK。
2. **`java install 17` 会返回已有的 21**：判断条件是 `major >= 目标`，于是
   「我要 17」被当成「21 也够」。改为大版本精确一致；`<root>/java` 下多套共存时
   按大版本挑可执行文件。顺带验证 `--china`：从清华 TUNA 拉下 jdk-17.0.21+9（41.8 MB），
   输出标了来源 `mirrors.tuna.tsinghua.edu.cn/Adoptium`。

另记一条不是缺陷的现象：跑起来后几秒到几十秒「正常退出」是测试时手动关的窗口，
`run` 报 `正常退出 code=0` 是对的。判断「游戏自己死了」靠的是日志心跳（ADR-0033），
日志以 `Stopping!` 收尾时不会被误判成崩溃。
