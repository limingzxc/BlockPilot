## 三条值得记住的坑

1. **`\s` 会跨行。** E2E-301 第一版改成 `/日志\s+(.+?\.log)/m` 仍然失败：
   `日志` 先匹配到上一行的「326 行日志」，`\s+` 吃掉换行，于是把「日志  D:\...」整个当成了路径。
   正确写法是行首锚定 + `[ \t]+`。
2. **「进程还活着」不是证据。** 未捕获异常打在渲染线程上时 JVM 不退出，`--stop` 到点
   我们照样 exit 0。只有日志心跳（安静 ≥20 s 且以栈帧收尾）能区分这两种情况，
   而健康但安静的整合包不会被误判，因为第二条判据不成立。
3. **兜底表会盖过模组自己的声明。** BTWCE 在 1.6.4 上要求 Java 17–21，而「MC 版本 → Java」
   推出来是 8。有 mod 声明时必须以声明为准，否则两条建议互相矛盾，用户照哪条都可能装坏。

## 附：真机验一次新命令（23:23–23:37）

不是发版验证，是「照 README 敲一遍」：

```
blockpilot forge 1.20.1 --root fixtures/mcroot --instance forge-cli --loader 47.3.22
  原版就绪  下载 1 · 跳过 65 · 原生库 54 个

  → Sound engine started / 全部 atlas 创建完成     # 没有 UnsatisfiedLinkError: lwjgl.dll
```

issue #13 里「手工装完 Forge 直接 run 会缺 natives」那条，在 `forge` 子命令下不复现：
它先跑原版 setup（解压 54 个原生库），再跑 installer。

同时撞出两个问题，都已修：

1. **`ASSETS_MISSING` 的提示不可执行**：给的是 asset index id（1.20.1 的 index 叫 `5`），
   `blockpilot assets 5` 会去取 `versions/5/5.json`，直接 404。改为提示 MC 版本。
   照修好的提示实跑：`assets 1.20.1` 补齐 fixtures 里真实缺失的 143 个对象
   （86.8 MB，0 失败），复检 verdict 从 WARN 回到 OK。
2. **`java install 17` 会返回已有的 21**：判断条件是 `major >= 目标`，于是
   「我要 17」被当成「21 也够」。改为大版本精确一致；`<root>/java` 下多套共存时
   按大版本挑可执行文件。顺带验证 `--china`：从清华 TUNA 拉下 jdk-17.0.21+9（41.8 MB），
   输出标了来源 `mirrors.tuna.tsinghua.edu.cn/Adoptium`。

另记一条不是缺陷的现象：跑起来后几秒到几十秒「正常退出」是测试时手动关的窗口，
`run` 报 `正常退出 code=0` 是对的。判断「游戏自己死了」靠的是日志心跳（ADR-0033），
日志以 `Stopping!` 收尾时不会被误判成崩溃。

## 追加：CurseForge 不再需要 key（2026-11-09 00:00–00:20）

用户对照 PCL2 提出的质疑：主流启动器都没有让人填 key。核实后的结论是
「启动器替用户付了」——Prism/ATLauncher 内置了登记过的 key；开源项目内置会泄露并吊销。
可行的对齐方式是走镜像，这也是国内启动器的做法。

实测 MCIM 的 `/curseforge` 代理（**不需要 key**）：

```
GET  /curseforge/v1/mods/238222              → 200，latestFiles 带 downloadUrl + hashes
GET  /curseforge/v1/mods/238222/files/3040523 → 200，downloadUrl 指向 edge.forgecdn.net
POST /curseforge/v1/mods/files（批量）         → 404，未代理
```

RLCraft 2.9.3 清单 187 个 fileID，逐个查：**187/187 解析、185 有直链、
3.8 秒**——与官方 key 的结果一致。于是改成「有 key 走官方批量，没 key 走镜像」。

真机无 key 部署（`env -u BLOCKPILOT_CF_API_KEY`，全新实例 rl2）：

```
· CurseForge 解析源：MCIM · mod.mcimirror.top
  装好了  1.12.2 + forge 14.23.5.2860
  模组 185 个（下载 185 / 失败 2）· overrides 3381 个文件（其中 mods/ 里 3 个 jar）
  部署后检查  WARN  ! ASSETS_MISSING（1.12.2 只影响声音，不影响启动）
```

失败 2 个仍是作者关闭第三方下载（SRParasites / RTG），与有 key 时一致。
另：`preflight` 里的 `CF_API_REQUIRED` 改名 `CF_NO_MOD_CHECK`——预检仍不做
CF 的 mod 级校验，但不再暗示「装不上」。ADR-0036。

## 追加 2：preflight 的 CF mod 级校验（2026-11-09 00:09–00:35）

既然文件元数据能免 key 拿到，`preflight <cf.zip>` 就不该只会说「做不了」。现在：

```
$ blockpilot preflight RLCraft-2.9.3.zip --no-host      # 没有任何 key
187/187  解析 CurseForge 文件
  verdict   WARN
  mods      187  (resolved 187, unresolved 0)
  ! UNVERIFIED_DEPENDENCY  Bountiful-1.12.2-2.2.3.jar 需要前置模组 351264，整合包里没有它
  i PACK_BUILTIN_MODS  overrides/mods 里还有 3 个 jar，解压后实例里共 190 个模组
```

- CF 的 `gameVersions` 是混合数组（`["1.12.2","Forge","Java 8"]`），拆成 MC 版本与加载器；
  作者没填的（空数组）**不判**版本/加载器，否则会产出假 blocker。
- 依赖检查能直接判：CF 的依赖给的是 modId，与 manifest 的 projectID 同一套编号。
  口径仍按 ADR-0025——只报 warning，并注明「可能已内置在 jar-in-jar 里」。
- 拿不到元数据的文件算 `unresolved`，verdict 落到 unknown，不给假通过。
- `--no-cf-mirror` 时不联网，退回原来的 `CF_NO_MOD_CHECK`（E2E-104 用的就是这条路，
  避免 T0/T1 依赖第三方镜像的可用性）。

单测 343 → 347；E2E T0 15/15、T1 7/7。
