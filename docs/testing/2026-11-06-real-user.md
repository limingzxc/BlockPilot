# 2026-11-06 真实用户实测（第四轮）：26.2 首启断在原生库目录

这轮换了顺序：**先看玩家此刻在装什么，再照 README 从零装一遍**。
素材是当场从 Modrinth 下载的线上包，不是 fixture；机器上原本没有 Java。

结论先说：装包这条路是通的（51 个文件、0 失败、17 分钟），
但**第一次启动必死**——26.x 的原生库目录换了布局，`extractNatives` 还在按 1.x 的写法放文件。
另外，上一轮记过的两个 P0 只修了一半：`selectJava` 改成读版本 JSON 了，
`preflight` 那张 Java 需求表还写着 21；`VERSION_MISMATCH` 的 ADR-0026 一直停在 Proposed。

## 4. 缺陷

### P0-1 · 26.x 的原生库目录变了，第一次启动必死

**现象**（`10-run.log`，第 217 行）：

```
Caused by: java.lang.UnsatisfiedLinkError: Failed to locate library: lwjgl.dll
	at org.lwjgl.system.Library.loadSystem(Library.java:177)
  异常退出  code=1 · 20.8s · 238 行日志
```

**根因**：26.2 的 JVM 参数（Mojang 自己写的）是：

```
-Djava.library.path=${natives_directory}/java
-Djna.tmpdir=${natives_directory}/jna
-Dorg.lwjgl.system.SharedLibraryExtractPath=${natives_directory}/lwjgl
-Dio.netty.native.workdir=${natives_directory}/netty
```

而 `src/core/setup/vanilla.ts` 的 `extractNatives` 把所有 DLL 直接倒进 `natives/<ver>/`：

```
natives/26.2/windows/x64/org/lwjgl/lwjgl.dll     ← 实际
natives/26.2/java/...                            ← JVM 去找的地方
```

`java.library.path` 指向一个不存在的目录，LWJGL 当然找不到。1.x 的参数是
`-Djava.library.path=${natives_directory}`（无子目录），所以 1.21.1 一直是好的——
这条只在 26.x 上暴露。

**影响**：装完第一次启动就崩；`diag` 会正确指向 natives 并建议「删掉 natives 重跑 setup」，
但重跑还是解到同一个错地方——用户会陷入循环。这是「装好了」与「能玩」之间唯一的断点。

**修法**：按版本 JSON 自己写的参数判定布局（不猜版本号），LWJGL → `java/`、
JNA → `jna/`、Netty → `netty/`，并把四个目录先建出来。旧版本保持原样。
新增 `src/core/setup/natives.test.ts` 4 条（两种布局各一条端到端解压）。

### P0-2 · 预检的 Java 需求表还写着 21（上轮 P0-1 只修了一半）

**现象**：

```
$ blockpilot preflight Fabulously.Optimized-v14.1.2.mrpack
  ✗ JAVA_MISSING  Minecraft 26.2 需要 Java 21，本机未检测到
    → 已检测到：无
```

**根因**：`requiredJavaMajor` 有两份实现（`java/types.ts` 与 `preflight/check.ts`），
两份都对日历版返回 21；上一轮修的是 `selectJava`（改成读版本 JSON），
`checkJava` 直接调表，没走那条路。单测还把 `26.3 → 21` 写死了。

**影响**：比「报错」更糟的是「报对了一半」——机器上只有 Java 21 时，
`checkJava` 认为精确匹配、**一条 finding 都不报**，预检 OK；启动时才死在
`UnsupportedClassVersionError`。没有 Java 的用户则被引导去装 21，装了也没用。

**修法**：只留 `java/types.ts` 一份，26.x → 25；preflight 改为引用它；
`JAVA_MISSING` 的 hint 从「已检测到：无」改成「已检测到：无 · 装一个再重试：
`blockpilot java install 25`」。两份测试同步更新，并新增一条「只有 Java 21 时必须报缺 25」。

### P1-1 · 同一个包，装前 BLOCKED、装后 OK（ADR-0026 落地）

上一轮已定性，ADR 也写好了，但代码没改。这次实测原样复现：

```
preflight <pack>      → BLOCKED / exit 2 / VERSION_MISMATCH
preflight <实例目录>   → OK      / exit 0
```

被判死的是 MixinTrace Reborn（下载量第一的包里一个 7 KB 的调试模组），
Modrinth 的 `game_versions` 只勾到 26.1.2，jar 内写的是 `minecraft: "26.x"`。

按 ADR-0026 落地：目标版本 **低于**模组最低声明 → 仍 `blocker/VERSION_MISMATCH`；
**高于**最高声明 → `warning/VERSION_UNVERIFIED`；命中区间但没勾（gap）→ 仍 blocker。
`semver.ts` 新增 `compareVersions`。

修完对同一个包：`WARN / exit 0`，finding 是 `VERSION_UNVERIFIED`，措辞不再说「不支持」。

### P1-2 · 文件下载没有空闲超时

`http.ts` 的 JSON 请求有 20 s 超时，`downloader.ts` 的文件下载一个都没有。
半死不活的 TCP 连接会让 `deploy` 永远停在 `23/51`，不报错也不结束。

修法：按「空闲」计时而不是总时长——连续 30 s 没收到字节就中终止、换下一个源。
新增测试：本地起一个只发 4 字节就不动的服务，断言 500 ms 内报错且不留 `.part`。

### P2-1 · `deploy` 把资源包算成模组

```
装好了  26.2 + fabric 0.20.1
模组 51 个（下载 51 / 跳过 0 失败 0）· overrides 51 个文件
```

包里只有 49 个模组，另 2 个是 `resourcepacks/`。修法：`DeployResult` 拆成
`files`（全部）与 `mods`（`mods/` 下），输出改成「模组 49 个（文件 51 个：…）」。

### P2-2 · `deploy` 选 Java 时不带游戏版本

`runDeploy` 调 `pickJavaOrReport(undefined, …)`：不知道要哪个版本，就只能「捡最高的那个用」。
机器上只有 Java 8 时会被当成可用，Forge installer 随后炸得莫名其妙；
提示也只有「没有找到可用的 Java」，不说要哪个版本。

修法：先用 `readPackFile` 读包里的 `gameVersion` 再选。修完的输出：

```
没有找到可用的 Java 25（本机：无）
可以装一个：blockpilot java install 25
```

### P3-1 · `java install` 命中缓存仍打印「下载完成」

用已存在的归档（sha256 校验通过、跳过下载）时，仍然输出「下载完成 55.9 MB，解压中…」。
实际一个字节都没下。属于文案，未改。

## 5. 观察：Java 自己下不动（未修）

`java install 25` 只认 Adoptium 给的 GitHub release 地址。这台机器上实测：

| 源 | 速度 | 55.9 MB 预计 |
|---|---:|---|
| GitHub（走代理） | 6–16 KB/s | 1–2 小时 |
| 清华 TUNA 同文件 | 23 MB/s | 2.5 秒 |

两边 sha256 一致（`da78d54a…beae`），是同一个字节流。`--china` 不影响这一步——
镜像只覆盖 Mojang / maven，不覆盖 Java 运行时。国内用户第一次装 Java 25 会卡在这里。

本轮为了继续测启动，用 TUNA 下载同一文件、校验 sha256 后放进 `mc/java/.cache/`，
再跑一次 `java install 25`，走的是「缓存命中 → 解压 → 探测」的正常路径（输出见 `09-java-install-cached.log`）。
**没有改代码**：加镜像要选源、要处理各家目录结构，属于功能而不是修 bug，留给下一轮决定。

## 6. 顺带修掉的用例耦合

`E2E-106` 没带 `--no-host`，在没装 Java 的机器上会因为 `JAVA_MISSING` 判 BLOCKED、
`install` 跟着退 2。这条用例验的是「未验证依赖默认不装」，与宿主 Java 无关，
已补 `--no-host`。

（由此浮出一个产品问题，本轮不改：`install` 的退出码继承预检 verdict，
意味着 CI 上没有 Java 时「补装模组」也会失败。要不要让 `install` 只对模组结论负责，
需要单独决定。）

## 8. 没测什么

- **T2/T3 全量**：本轮只手工走了一条真实链路（deploy → run）；没有跑 `--tier 2,3` 套件。
  启动验证依赖本机 GPU/窗口，结果只在这台机器上成立。
- **assets**：482 MB，只下了索引，没验「装完有声音」。
- **Forge / NeoForge**：FO 是 Fabric 包；Forge installer 那条路本轮没碰。
- **正版登录、CurseForge 安装**：与上轮相同，缺账号与 API key。

## 一句话

**「装好了」和「能玩」之间，隔着一个目录名。**
预检说 BLOCKED 的包能装、能跑；部署后检查说 OK 的包起不来——
两处都是「手上的证据只够说这么多，却说多了」。
